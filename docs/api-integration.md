# Watchdog API — описание для интеграции

Документ для разработчика, который подключает внешний сервис к Watchdog.
Все примеры проверены на работающем экземпляре.

**Базовый адрес:** `http://172.30.50.200:8090`

Все пути ниже даны относительно него.

---

## 1. Авторизация

Каждый запрос несёт заголовок с токеном:

```
Authorization: Bearer agg_392f372d039ca3a1200f7bc2c0b19af5bfbddb0cb807f1c044ec49c17e4a32fc
```

Токен действует от имени своего владельца и видит ровно то, что видел бы он.
Срок жизни задаётся при выпуске; токен без срока живёт вечно.

Без заголовка или с неверным токеном приходит `401`:

```json
{"detail": "Потрібна авторизація"}
{"detail": "Недійсний токен"}
```

Куки и двухфакторный код для интеграции не нужны — только заголовок.

### Управление токенами

| Действие | Запрос |
|---|---|
| Выпустить | `POST /api/tokens` |
| Список | `GET /api/tokens` |
| Отозвать | `POST /api/tokens/{id}/revoke` |

Выпуск:

```bash
curl -X POST 'http://172.30.50.200:8090/api/tokens' \
  -H 'Authorization: Bearer <существующий токен>' \
  -H 'Content-Type: application/json' \
  -d '{"name": "billing-service", "expires_in_days": 90}'
```

`expires_in_days` можно не указывать — тогда токен бессрочный.

```json
{
  "id": 2,
  "name": "billing-service",
  "prefix": "agg_7f3a91",
  "created_at": "2026-09-24T10:00:00+00:00",
  "last_used_at": null,
  "expires_at": "2026-12-23T10:00:00+00:00",
  "revoked": false,
  "token": "agg_7f3a91c4...полный токен..."
}
```

Поле `token` приходит **только в этом ответе и больше нигде**. В базе хранится
лишь его хеш, восстановить значение нельзя. Потерял — выпускай новый.
В списке токенов видно `prefix` — короткое начало, по нему токен опознаётся,
но воспользоваться им нельзя.

## 2. Поиск по собранным сообщениям

Основная точка интеграции.

```
POST /api/v2/events/search
Content-Type: application/json
```

Все поля тела необязательные. Пустое тело `{}` вернёт самые свежие сообщения.

| Поле | Тип | Что делает |
|---|---|---|
| `q` | строка | слова в тексте; должны присутствовать все; регистр не важен |
| `contains` | строка | подстрока в тексте: кусок кошелька, ник внутри сообщения |
| `author_id` | строка | Telegram id отправителя, точное совпадение |
| `nickname` | строка | ник отправителя, частичное совпадение |
| `phone` | строка | телефон отправителя; нецифры отбрасываются |
| `target_id` | число | конкретный канал (см. раздел 5) |
| `parser_type` | строка | `telegram`, `darknet` или `whatsapp` |
| `since` | дата-время | включительно, ISO 8601 |
| `until` | дата-время | исключительно, ISO 8601 |
| `limit` | число | 1..500, по умолчанию 100 |
| `cursor` | строка | продолжение выборки, см. раздел 3 |

Несколько полей сочетаются по «и»: `{"q":"обнал","target_id":1}` найдёт слово
только в этом канале.

### Чем `q` отличается от `contains`

`q` ищет **слова целиком**. `contains` ищет **любой кусок текста**.

Запрос `q: "курьер"` не найдёт сообщение со словом «курьеры» — это разные слова.
Запрос `contains: "курьер"` найдёт, потому что это подстрока.

На рабочих данных разница заметная:

| Запрос | Найдено |
|---|---|
| `q: "курьер"` | 205 |
| `q: "курьеры"` | 113 |
| `contains: "курьер"` | 310 |

Для адресов криптокошельков, номеров и ников внутри текста нужен `contains`:
целым словом такое не ищется.

### Пример

```bash
curl -X POST 'http://172.30.50.200:8090/api/v2/events/search' \
  -H 'Authorization: Bearer <токен>' \
  -H 'Content-Type: application/json' \
  -d '{"q": "курьеры наличных", "since": "2026-09-01T00:00:00Z", "limit": 50}'
```

### Ответ

```json
{
  "items": [
    {
      "parser_type": "telegram",
      "target_id": 1,
      "account_id": 1,
      "owner_user_id": 1,
      "external_id": "379308",
      "event_key": "379308",
      "observed_at": "2026-09-24T14:09:01.000+00:00",
      "event_kind": "message",
      "thread_id": "-1001536841242",
      "reply_to": "",
      "author_id": "8685081509",
      "author_label": "@ShrekExz",
      "sender_phone": "",
      "text": "В доступности на принятия любых средств...",
      "ingested_at": "2026-09-24T14:09:03.110+00:00"
    }
  ],
  "next_cursor": "MTc5MDI1ODk0MTAwMDozNzkzMDg=",
  "limit": 1
}
```

Поля записи:

| Поле | Смысл |
|---|---|
| `parser_type` | источник: `telegram`, `darknet`, `whatsapp` |
| `target_id` | внутренний номер канала |
| `external_id` | номер сообщения в источнике |
| `event_key` | ключ записи; вместе с `parser_type` и `target_id` уникален |
| `observed_at` | когда сообщение появилось в источнике |
| `ingested_at` | когда мы его записали |
| `event_kind` | `message` или `comment` |
| `thread_id` | ветка форума или обсуждение, если есть |
| `reply_to` | на какое сообщение отвечает |
| `author_id` | Telegram id отправителя |
| `author_label` | ник или отображаемое имя |
| `sender_phone` | телефон, только цифры; чаще всего пустой |
| `text` | текст сообщения |

Сортировка: сначала самые свежие (`observed_at` по убыванию).

**Общего числа найденного нет намеренно.** Точный подсчёт на больших объёмах
означает полный перебор таблицы. Листайте курсором.

## 3. Постраничный обход

В ответе приходит `next_cursor`. Чтобы получить следующую страницу, положите
его в тело следующего запроса, не меняя остальные поля:

```json
{"q": "обнал", "limit": 200, "cursor": "MTc5MDI1ODk0MTAwMDozNzkzMDg="}
```

Когда `next_cursor` равен `null` — страницы закончились.

Курсор непрозрачный: не разбирайте и не собирайте его сами, формат может
измениться.

## 4. Полное сообщение источника

В выдаче поиска приходит только текст. Сырой объект от Telegram тяжёлый, за ним
идёт отдельный запрос:

```
GET /api/v2/events/{parser_type}/{target_id}/{event_key}
```

```bash
curl 'http://172.30.50.200:8090/api/v2/events/telegram/1/379308' \
  -H 'Authorization: Bearer <токен>'
```

Ответ повторяет запись из поиска и добавляет `payload`:

```json
{
  "parser_type": "telegram",
  "target_id": 1,
  "event_key": "379308",
  "text": "...",
  "payload": {
    "event_type": "telegram_message",
    "message_id": 379308,
    "date": "2026-09-24T14:09:01+00:00",
    "chat_id": -1001536841242,
    "text": "...",
    "sender": {"id": 8685081509, "username": "ShrekExz", "first_name": null, "last_name": null},
    "raw": { "полный объект Telegram: id, peer_id, media, entities, reply_to, ..." },
    "source": "telegram_listener"
  }
}
```

`payload.raw` — нетронутый объект от Telegram. Там лежит всё, чего нет в плоских
полях: вложения, форматирование, пересылки, реакции.

Если записи нет — `404`.

## 5. Справочники

Чтобы сопоставить `target_id` с настоящим каналом.

### Каналы

```
GET /api/modules/telegram
```

Ответ содержит `targets`, `accounts`, `jobs`, `summary`. Для интеграции нужен
`targets`, где у каждого объекта есть:

| Поле | Смысл |
|---|---|
| `id` | тот самый `target_id` из поиска |
| `name` | название канала |
| `identifier` | `@имя` или `-100…` |
| `kind` | `channel`, `group`, `private` |
| `group_id`, `group_name` | категория |
| `is_active` | собирается ли |
| `events_count` | сколько собрано |
| `last_event_at` | когда было последнее сообщение |

### Категории

```
GET /api/modules/telegram/groups
```

```json
{"groups": [{"id": 1, "name": "Дропи та схеми", "position": 0, "targets": 6}]}
```

## 6. Как забирать новое

Рекомендуемый способ для постоянной интеграции.

1. Запомните `observed_at` самой свежей обработанной записи.
2. Раз в N минут запрашивайте `{"since": "<это значение>", "limit": 500}`.
3. Если пришёл `next_cursor` — дочитайте страницы, пока он не станет `null`.
4. Обновите отметку.

Граница по времени включительна, поэтому на стыке могут повторяться записи.
Отсеивайте дубликаты по тройке `parser_type` + `target_id` + `event_key` — она
уникальна.

Не опрашивайте чаще, чем раз в минуту: сообщения приходят потоком, но новых за
несколько секунд обычно нет.

## 7. Ошибки

| Код | Когда |
|---|---|
| `400` | неверный `parser_type` или испорченный `cursor` |
| `401` | нет токена, токен неверный, отозванный или просроченный |
| `403` | объект принадлежит другому пользователю |
| `404` | запись или объект не найдены |
| `422` | тело не проходит проверку (например `limit: 0`) |
| `503` | хранилище событий недоступно |

Тело ошибки всегда одной формы:

```json
{"detail": "Некоректний cursor"}
```

---

## 8. Что нужно знать заранее

**Видимость.** Токен видит только объекты своего владельца. Токен администратора
видит все.

**`limit` подрезается молча.** Запросили 5000 — получите 500, и в ответе будет
`"limit": 500`. Ориентируйтесь на значение из ответа, а не на своё.

**Ограничения частоты запросов сейчас нет.** Не злоупотребляйте: защиты от
перегрузки тоже нет.

**Соединение без шифрования.** Адрес доступен только внутри защищённой сети.
Токен по открытому каналу не передавайте.

**Телефоны почти всегда пустые.** Telegram отдаёт номер, только если наш
собирающий аккаунт держит человека в контактах. Поле есть, данных в нём мало.

**Поиск по словам не знает морфологии.** «работа» и «работы» — разные запросы.
Если нужны все формы, перечисляйте их или пользуйтесь `contains`.

**Старый поиск** `GET /api/search/messages` работает по другой базе и оставлен
для интерфейса. Для интеграции используйте `POST /api/v2/events/search`.
